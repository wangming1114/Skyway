# VLESS-WS-TLS 真机验收与回归

2026 年 11 月 21 日，在用户指定的 IPv4 VPS 上运行 sing-box 1.14.4 和 Caddy 2.11.9。本机使用工作区构建的 Skyway、独立的 MySQL 5.7 和 Redis，通过真实管理接口操作 VPS。公网验收使用 `skyway666.sbs` 的临时子域名、Cloudflare DNS、Let's Encrypt 和 Mihomo 1.19.33。

## 节点与客户端

| 验收项 | 实际观察 |
| --- | --- |
| 创建及幂等 | 从 VPS 的 HTTP 接口重复提交相同操作 ID，只创建一个节点。从 WebSocket 提交另一个节点后立即关闭页面，后台仍完成签发与握手。自填前缀和自动分配都创建了真实的 A 记录，默认关闭橙云。 |
| 共用 443 | 两个 Mihomo 客户端经同一公网 443 同时连接，各自上传和下载 6 MiB，并校验响应。还通过 Mihomo 的 SOCKS5 UDP 关联分别在直连与橙云路径收到了源站返回的相同随机报文。两个独立本机端口都采到了非零的上下行实时速率。Quartz 采集后的两条流量记录均有独立的收发增量。 |
| 限速与日志 | A 的下载、上传上限分别为 12、8 Mbps，B 为 24、16 Mbps。四条内核限速规则都命中了数据，三条出现了超限丢包。实际访问日志 WebSocket 为两个节点分别返回了匹配各自入站标签的记录。限速到期后，仅 B 的有效限速被撤销。 |
| SOCKS5 和域名策略 | 使用带认证的临时 SOCKS5 服务核对转发命中。在白名单、黑名单模式下分别验证放行和拦截，同一公网端口上的另一个节点仍能访问。批量清空策略并关闭中转后恢复直连。客户分享中未检出中转凭据。 |
| 橙云和证书 | Cloudflare API 回读橙云状态，通过带 `CF-Ray` 的边缘节点完成双向传输。触发真实维护任务重新申请源站证书，指纹改变后继续传输。关闭橙云后恢复直连。叶证书私钥保存在 VPS。 |
| 换域名和端口 | 橙云模式拒绝 8123。将节点从 443 迁到新域名的 8443 后，旧 DNS 记录按 ID 查询返回 404。保持运行的 Mihomo 刷新原订阅后完成双向传输。节点 ID、UUID、本机端口、累计流量和限速保留。 |
| 停用、到期和转交 | 手动停用及实际到期任务均停止数据连接，订阅返回 404，DNS 保留。恢复后继续使用原地址。节点转交另一客户后，旧订阅返回 404，原客户的分享页中移除了该节点。 |
| 管理端和客户页 | Chrome 核验了管理端节点详情、订阅信息、客户密码解锁、连接参数、原始链接复制和 YAML 下载。两端下载的 YAML 均指向正确节点。分别解码二维码原图及页面截图，结果逐字匹配原始 VLESS 链接。额外的离线扫码样本覆盖 1、32 和 63 字符的子域名前缀。 |
| 浏览器批量操作 | 从客户详情页创建两行，第一行成功，第二行因重名失败。改正前缀后使用“只重试失败项”，只提交了改正的行。随后分别使用 WebSocket 和 HTTP 单删，并按记录 ID 核验 DNS 清理。 |

## 故障、数据和安装

| 验收项 | 实际观察 |

| 异主记录 | 专门创建一条带其他归属标记的临时 DNS 记录。同名节点创建被拒绝，记录 ID、内容及标记均保持原值。随后由测试按该记录 ID 单独回收。 |

| 签发失败 | 在测试管理端注入 ACME 目录 503。节点先创建真实 DNS，三次签发失败后回收记录，节点列表未出现成功项。恢复真实 CA 并重启后，复用同一个操作 ID 创建成功。 |

| 离线强删和恢复 | 在隔离管理库清除测试实例的 SSH 凭据，VPS 持续在线。强删节点完成云端清理。强删 VPS 遇到同一 DNS 故障后保留待办，恢复提供方并重启 Skyway 后自动完成。最后核对有效限速、域名绑定、节点流量、快照及待处理任务均为零，并回收源站测试残留。 |
| 数据库 | 在三个独立 MySQL 5.7 库分别执行存量升级、新装和 Docker 初始化。核对 WS 表、字段、索引及配置一致，并核验旧节点数量与原字段兼容。 |
| 全新 Caddy | 在没有预装 Caddy 的 Alpine 容器中验证官方发布包校验、自动安装、OpenRC 注册、启动以及 HTTPS 反向代理。指定 VPS 上则验证了追加站点与原有 Caddy 共存。 |

## 本轮修复

- 真实 Spring 管理端暴露了 WS 仓储代理的字段访问问题，会导致后台维护抛出空指针。WS 服务改为通过仓储方法取得依赖，生命周期回归使用与应用相同的类代理。
- 一条 301 字符的 WS 链接在原有 220 像素二维码上无法被两种解码器识别。WS 分享现在按每个二维码模块 6 个像素生成，并留出 4 个模块的边距。这条链接的新原图为 462 × 462，客户页和管理端的实屏截图也可解码。其他协议沿用原二维码选项。
- Caddy 2.11.9 发布清单使用 SHA-512。WS 新装脚本现严格核对指定文件的唯一 SHA-512 条目。arm64 和 amd64 发布包同时与 GitHub 资产 SHA-256 和官方 SHA-512 清单匹配。已将全新系统安装测试接入本地回归脚本。[Caddy 官方校验清单](https://github.com/caddyserver/caddy/releases/download/v2.11.9/caddy_2.11.9_checksums.txt)

## 其他功能回归

- 在同一 VPS 上，Hysteria2 和 VLESS-REALITY 分别通过创建、分享、修改端口、Mihomo 双向传输、流量统计和删除。VMess-TCP 通过真实管理接口创建，解码原始分享后，客户端在改端口前后均完成了双向传输。
- 旧节点编辑及域名策略专项通过。原有采集器会把正在采集的协议跳转规则移到链首。最初的域名策略测试因此把相邻 TCP 与 UDP 跳转互换判成失败。测试现在只归一化同一目标链上相邻、仅按协议匹配的这两条跳转，仍检查其他规则及相对顺序。旧采集器业务代码保持原版本。
- 主机的两个公网网卡已有活动限速。会重建整机队列的历史 Hysteria2 综合压测没有直接运行。另在同一 VPS 的独立网络及挂载命名空间运行原限速脚本，在独立网卡和 IFB 设置 4、6 Mbps，每个方向传输 1 MiB，检查内核分类字节数及撤销后的规则。
- Chrome 回归了原客户站的受保护路由、登录页滑动校验提示、个人中心、产品页和退出。该用例通过实际客户登录 API 获取会话。管理端登录、权限菜单、客户列表及客户分享密码隔离均通过。

## 本机 IDE 签发故障复验

此前的公网测试显式指定了 lego 路径。本机 IDEA 启动的 Skyway 在创建节点时找不到 `lego`，安装工具后又遇到管理机直连权威 DNS 超时。修复后沿用用户提交的原操作 ID 完成了创建。

- 在独立的临时目录中移除测试进程 PATH 对 lego 的可见性，使用与管理服务相同的 JDK 实际下载并校验官方 v4.26.0。运行 `--version` 成功，第二次解析复用了同一可执行文件。回归用例还验证了显式路径错误会在写 DNS 前结束，发行包校验失败会保留已有工具。
- 客户节点的 A 记录从公网解析到指定 VPS。源站和正常公网解析两条连接均通过了受信任证书及主机名校验，协商出 TLS 1.3，WebSocket 升级返回 101。Chrome 的 VPS 详情页刷新后显示新节点。
- 通过开发前端的固定订阅地址取得 HTTP 200，核对了 YAML 的域名、端口、UUID、WS Host、路径和 TLS。Mihomo 1.19.33 直接加载该订阅，经节点发起 HTTPS 请求取得 200，回显出口为该 VPS 的公网 IP。
- 修复后重新打包成功。隔离 Docker 回归在 166 项 Java 测试中运行了 161 项，全部通过，另外 5 项需单独提供真机环境。管理前端 89 项测试全部通过。
