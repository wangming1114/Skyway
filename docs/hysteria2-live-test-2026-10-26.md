## 真机发现并修复的问题

1. **多节点默认出站串用。** 只有入站的节点会继承合并配置中的首个出站，实际误走另一节点的 SOCKS5。新建节点现在使用独立标签的直连回退，中转与域名策略仍优先匹配；HTTP 和 WebSocket 共用这一初始化步骤。存量配置保持原内容。
2. **编辑端口缺少远端占用检查。** 原先只依赖数据库中的节点占用信息。现在替换配置前检查真实 TCP/UDP socket、配置文件和 Docker 映射，占用时不写入配置。

两个问题均补充了自动化回归测试；原有 VLESS 端口往返测试同步验证独立回退路由随入站标签更新。

## 验证范围和审计

- 存量节点配置、主配置、TLS 证书及私钥以测试前 SHA-256 清单核对。
- 存量节点的回环目标探针前后结果相同。该目标为服务器本机的测试 HTTP 服务，存量默认/显式 SOCKS5 出站会拒绝此类目标；这一探针不代表存量出口公网可用性。旧协议的实际功能连通使用独立临时节点验证。
- 默认本机路由经过 utun7 时，公网 UDP 探针未到达服务器。独立测试客户端选择 en0 后公网 TCP/UDP 通过；系统代理和路由未修改。
- 第三方转换使用虚构节点验证，确认密码、ALPN、证书指纹和跳过校验字段被保留。自动审批拒绝发送真实临时节点凭据，因此没有向第三方上传这些凭据。
- 临时节点、辅助进程、命名空间、veth、测试 nft 表和限速均在测试后清理；保留安装的采集依赖、平台脚本和审计备份。
- tc 解除限速后会回到内核默认 `fq`。清理阶段已按快照恢复 eth0/eth1 原有 `fq_codel` 算法及全部参数；内部 qdisc 句柄由内核重新分配。
- 服务器最终审计结果保存为上述备份目录中的 `final-audit.json`。

常规 Java 回归与带凭据的真机测试分开执行，避免普通构建访问真实服务器。真机入口为 `Hysteria2VpsLiveIntegrationTest`，使用 `SKYWAY_LIVE_HOST`、`SKYWAY_LIVE_PASS`、`SKYWAY_LIVE_MIHOMO` 环境变量；隔离客户端模式另设 `SKYWAY_LIVE_REMOTE_CLIENT=1`，需要预先准备受保护的备份目录和远端校验过的 Mihomo 客户端。
